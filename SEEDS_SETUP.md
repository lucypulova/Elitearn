# Elitearn – Database seeds setup (Schema + Demo data)

Seed файловете в Elitearn инициализират базата данни (схема + зависимости + demo данни) по **повторяем** и **контролиран** начин.

## Какво точно правят seed файловете

1. Създават таблиците и релациите (FOREIGN KEY, UNIQUE ограничения).
2. Създават индекси за често използвани заявки (където е приложимо).
3. Зареждат начални (demo) данни – потребители/курсове/категории и др. (когато файлът го съдържа).
4. Подготвят помощни структури за функционалности като:
   - покупки/поръчки,
   - чат,
   - outbox за имейли,
   - статистика за търсения и препоръки.

> Практически: seed-овете са “инсталатор” на базата – правят средата готова за работа и демонстрация.

## Where to place your DB credentials / connection string

Конфигурацията за връзка към базата се задава **само** в:

- `backend/.env`  (създайте файла, ако липсва; или редактирайте вашия съществуващ)


### Минимална проверка, че сте на правилното място
- Стартирайте backend-а от директория `backend/`.
- Проверете, че `.env` е точно в `backend/.env` (не в root-а и не във frontend).

## Къде се намират seed файловете

- `backend/seed/`

Файловете са **номерирани** (01, 02, 03…), за да се изпълняват в правилен ред (важно за FOREIGN KEY зависимостите).

## Как са организирани (примерна логика)

Типична организация:

- `01_core_schema_and_seed.sql` — основни таблици (потребители/профили/общи зависимости)
- `02_courses_schema_and_demo_data.sql` — курсове, категории и demo записи
- `03_accounts_orders_cart_schema.sql` — количка, поръчки, order items
- `04_chat_schema_and_demo_data.sql` — чат таблици и demo данни
- `05_profile_avatar_support.sql` — поддръжка на профилна снимка (avatar)
- `06_search_telemetry.sql` — статистика за търсения + базова структура за препоръки

> Забележка: реалните имена във вашия архив са тези в `backend/seed/` и се изпълняват по номерация.

## Как да заредите seed-овете (schema + demo data)

Ръчно през SQL клиент:

#### 1) Създайте празна база

Създайте база (примерно `elitearn`), според избраната СУБД.

#### 2) Изпълнете файловете **в правилния ред**

**macOS / Linux (bash):**
```bash
# пример с mysql CLI
for f in backend/seed/*.sql; do
  echo "Running $f"
  mysql -u <USER> -p <DB_NAME> < "$f"
done
```

**Windows (PowerShell):**
```powershell
Get-ChildItem backend/seed/*.sql | ForEach-Object {
  Write-Host "Running $($_.FullName)"
  mysql -u <USER> -p <DB_NAME> < $_.FullName
}
```

> Ако използвате PostgreSQL, заменете `mysql ...` с `psql ...` според вашата конфигурация.

## Как да проверите, че зареждането е успешно

1. Проверете дали таблиците са създадени (например `users`, `courses`, `orders`, `notification_outbox` и т.н.).
2. Проверете дали има demo данни .
3. Стартирайте backend-а и отворете каталога от frontend – трябва да виждате курсове/категории.

## Notes

- При повторно зареждане върху вече съществуваща схема е възможно да получите грешки от тип:
  - “table already exists”,
  - “duplicate key”,
  - “constraint violation”.
  В такъв случай се препоръчва:
  - да изтриете базата и да я създадете наново, или
  - да изпълните seed-ове върху чиста база.
